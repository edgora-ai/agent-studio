# 核心功能与关键场景

版本：v0.4；日期：2026-10-30；以下为验收场景设计，不是已完成测试。

## 功能分组

| 功能 | 用户看到的能力 | 边界 |
|---|---|---|
| 项目与环境 | 本地项目、Coder 工作区、启动状态、当前目标 | 项目不等于主机；同一代码库在不同环境中是不同绑定，不自动同步 |
| 会话执行 | 请求 Agent、流式结果、审批、取消、后台任务 | 每个任务固定其启动绑定；界面切换不改变运行位置 |
| 文件与搜索 | 文件树、打开、保存、文件名搜索、内容搜索、代码引用 | 不从路径字符串推测环境；搜索／文件结果携带绑定身份 |
| 修改审阅 | Git 状态、Diff、Agent 改动和未保存草稿冲突提示 | 首期远程结构化 Git 以只读为必需；写操作按下表，不承诺完整 IDE 操作集 |
| 环境安全 | 模板、资源配额、文件／网络／凭据策略、停止与回收 | SSH 连接成功不表示安全策略已落实 |
| 生命周期 | 创建、启动、停止，以及外部重建／销毁／凭据变化后的状态处理 | 产品内破坏性入口待确认；未提供时明确拒绝；停止不等于删除；级联结果可观察 |
| 传统 IDE | 从当前项目打开中央 code-server | 第二阶段；不通过每工作区部署 IDE 绕过单份目标 |

以下 `绑定` 指项目、环境、远程根目录、实例世代及策略的稳定组合，具体对象见[架构文档](03-system-architecture.md)。

## 首期 Git 能力范围

下表约束新增远程结构化入口和侧边栏适配；本地已有功能保留并回归，不因远程能力限制而移除。P1 增强项不计入首期 P0 完成条件，启用前必须另有能力声明和测试。

| 操作 | 首期远程结构化支持 | 授权与验收边界 |
|---|---|---|
| `status` | P0 必需 | 读取绑定仓库状态；验证不会读取中央同名仓库 |
| `diff`，包括工作树与暂存区 | P0 必需 | 结果带绑定身份；大输出有界，打开文件仍在原环境 |
| `log`／`show` | P1 增强，未适配时禁用 | 启用后按只读能力单独验证，不能据此声称支持写操作 |
| `add`／暂存 | P1 增强，首期默认禁用 | 后续结构化入口需明确文件范围、用户授权和索引读回 |
| `commit` | P1 增强，首期默认禁用 | 后续需用户授权、明确作者配置及提交事实验证；不能隐式创建身份 |
| `checkout`／`switch` | 首期不提供 | 不在切换项目时隐式切分支或改工作树 |
| `reset`／`clean` | 首期不提供 | 不把破坏性仓库清理作为普通刷新／恢复操作 |
| `push` | 首期不提供 | 不自动使用中央 Git 凭据，不隐式发布代码 |

“默认禁用／不提供”指没有可用的结构化入口，不是 OS 层禁止该 Git 子命令。用户仍可通过 FR-05 的通用命令能力明确请求 Git 写操作，但必须按动作、目标和副作用获得授权，执行、凭据与审计仍受绑定策略约束；这种执行不能算作侧边栏／结构化 Git 已支持该操作。远程未适配入口不能退回中央执行。

## SC-01：保留本地项目体验

**需求：** FR-01、FR-03、FR-04、FR-05、FR-06、FR-07。

- 前提：中央 dsh 可用，本地项目已登记；Coder 服务可暂时不可用。
- 操作：选择本地项目，浏览文件、搜索、编辑，执行测试并查看 Git Diff。
- 预期：所有操作留在原本的本地执行世界；不为本地项目创建云工作区，不要求 SSH 或 helper。
- 反例：远程适配器全局接管后，本地项目也被转发到最近一次连接的工作区。
- 证据：本地随机文件读写、命令环境标记、Git 仓库路径；Coder 停止时本地功能仍可工作。

## SC-02：从中央入口启动并打开云项目

**需求：** FR-01、FR-02、FR-03、FR-08、FR-11、FR-13。

- 前提：已配置 Coder 连接，账号对允许的目标模板和已有工作区有权访问；受控模板／部署过程可独立登记预期 workspace、agent、实例世代、预置标记、账号及允许根目录。新建分支在资源创建后、项目访问开放前取得该记录，不预先假定新工作区 ID。登记记录由模板构建过程产生，不从待测连接写回。
- 分支 A——启动已有工作区，必测：从中央入口列出并选择已停止的专用工作区，启动、等待就绪，选择项目根目录并核验身份；读回停机前写入的测试文件，确认没有误建替代工作区或丢失项目数据。
- 分支 B——新建工作区，必测：从中央入口选择允许模板并创建专用工作区，观察构建、Agent／helper 就绪和目标身份核验，再建立项目绑定、读取文件及执行无副作用的环境标记命令。不得在 Coder 控制台手动预建后，将导入或启动冒充产品内的新建链路通过。新建分支必须核对模板为本次构建生成的随机标记，且该标记来自模板构建记录而不是创建 API 的回显。
- 预期：生命周期状态、Agent／helper 执行通道就绪与目标身份核验分别呈现。全部满足条件后才允许项目文件和执行；入口地址保持不变。
- 异常：未授权、模板失败、配额不足、启动超时、Agent 未连接和身份不匹配，应显示各自原因；启动超时按 NF-07 的时限判定。
- 模板负向测试，必测：通过 Agent Studio 的服务端创建入口提交不在允许范围内的专用测试模板 ID，必须被拒绝，并核对平台资源／构建记录确认未创建工作区；仅隐藏 UI 选项不算通过。平台无权模板的拒绝也应分别记录，不替代产品自身的允许范围校验。
- 身份负向测试：故意使用错误工作区／账号／根目录或旧实例记录；即使该目标能完成随机文件读写，也必须被拒绝。预期标记不能通过待测连接临时写入后原路读回取得。
- 证据：两条分支分别保存实际资源、构建／生命周期记录、独立部署记录、预期与观察身份对照、项目绑定、文件读回和拒绝事件。创建请求／资源身份必须可关联，不能只检查 API 返回值。
- 通过条件：分支 A、分支 B 及模板／身份负向测试均通过，才算 SC-02 通过；任何一条未执行不得以其他分支替代。

## SC-03：同名目录的本地／远程切换

**需求：** FR-01、FR-03、FR-04、FR-06、FR-07、FR-09。

- 前提：本地和远程各有 `demo` 项目，文件名和路径相似，但包含不同随机标记。
- 操作：在项目选择器中切换；分别打开文件、搜索标记、保存改动并查看 Git。
- 预期：每次只影响选定绑定；浏览缓存、编辑标签和搜索结果均按绑定隔离。
- 会话规则：切换项目后打开该绑定已有会话或创建新会话，不静默修改旧会话的绑定。
- anchor 契约：受信任内部上下文中的当前 anchor 经核对后转换为远程根目录；公开 cwd 只按该远程环境路径解析，不查询 anchor 映射。未知／其他绑定的内部 anchor、根目录外的公开路径和显式中央执行请求均被拒绝；同名合法路径只能访问绑定环境，不访问中央。
- 上下文分类：适配层必须能判定一次调用来自内部工作区上下文还是公开工具参数。无法判定时拒绝，不按路径形状猜测。证据须包含一次“公开 cwd 恰好等于 anchor 路径”的用例，且不得被当作内部映射接受。
- Git 范围：验证首期 P0 的 status 及工作树／暂存区 Diff；未适配的结构化写入口不可用，不能走中央补偿。不要用一次通用 shell 提交代替侧边栏写能力验收。
- 证据：直接检查两端文件和 Git 差异、内部转换及拒绝事件，证明没有串写；删除远程映射后旧结果不能落到本地路径。

## SC-04：跨两台机器执行同一个类型的任务

**需求：** FR-03、FR-04、FR-05、FR-08、FR-11、FR-13。

- 前提：两个隔离工作区位于不同机器或 K8s 节点，有不同运行时标记和测试输入，且由冻结版本的模板创建。
- 操作：在各自会话委派读取输入、计算结果、创建输出文件、运行测试。
- 预期：主代理仍在中央；命令与文件修改均发生在对应环境。所有工具调用、容器／进程事实与输出能关联到绑定和实例世代。
- 验证：随机输入防止凭提示猜测；分别直接读回输出；中央宿主同名文件不变。
- 边界：K8s 验收必须记录实际节点；裸 Docker 验收必须记录实际远程主机，不能用同机两个容器冒充跨主机测试。
- 证据：两个环境的模板版本、实例记录、节点／主机标识与输出读回。

## SC-05：Agent 修改与手动编辑并发

**需求：** FR-04、FR-06、FR-07、FR-11、FR-13。

- 前提：侧边栏存在未保存草稿，Agent 修改该文件；第二阶段 code-server 也可能成为外部写入者。每条测试标注写入是否经过受管保存接口。
- 操作：Agent／外部编辑器完成改动后，再尝试保存基于旧版本的草稿；另以两个受管客户端基于同一版本保存。
- 预期：已观察到外部版本变化时提示冲突并可比较，不丢弃草稿；两个受管写入者竞争时只允许一个按原版本提交，另一个返回冲突。保存成功后能再次读回。
- 限制：直接写磁盘的进程不自动遵守版本令牌。最后一次版本检查到提交之间的外部竞争须单独记录，不以顺序测试宣称已消除；若未约束全部写入者，必须披露 `externalWriterRaceFree: false` 或等价能力状态。
- 证据：原始版本、Agent／外部版本、草稿、受管写入结果与冲突事件；同时检查能力声明及 UI 的限制提示。文件监听只是通知，不能替代保存时版本校验。

## SC-06：远端断线但任务可能仍在执行

**需求：** FR-03、FR-05、FR-09、FR-11。

- 前提：远端有持续写入测试标记的受控任务，已保存完整远程任务身份。对兼容矩阵中启用的每条执行通道分别测试；未启用的兼容通道验证拒绝派发，不强制为了测试而引入第二条通道。
- 操作：中断中央到远端的连接，再恢复；也测试 Coder 显示运行但执行通道不可用的情况。
- 预期：显示连接中断和任务状态未知；不自动重新执行、不自动切到本地、不将未知标成成功。连接恢复且原环境健康后，必须凭已保存身份重查原任务的运行／退出事实，并能对仍在运行的原任务发起受管取消。
- 恢复窗口：重连必须发生在 adapter 声明的恢复窗口内；窗口长度与超时后的期望状态按 NF-07 记录。窗口内查不到原任务判为失败；明确超过窗口的用例记录为“窗口外”，同样不得当作通过。
- 重传：按架构的去重协议契约注入 ACK 丢失、并发重复请求、同键不同参数、去重日志过期、daemon 重启和实例切换。已登记且身份／参数一致的重复请求只返回原结果或原运行句柄；直接核对副作用计数为一次。同键不同参数必须拒绝；日志或实例身份不可确认时保持未知，不重新执行。不能用最终文本相同或重传次数少于两次代替证明。未实现去重能力的通道必须禁用有副作用请求的自动重传，并验证禁用确实生效。
- 取消：取消请求无法送达时显示“取消待确认”，不能立即宣称已经停止。
- 证据：重连后的远程进程／资源事实、唯一操作 ID、副作用计数及中央状态变化；实际启用的执行通道分别记录，并保留未启用路径的拒绝证据。

## SC-07：取消、超时、停止与删除各有不同语义

**需求：** FR-02、FR-05、FR-08、FR-09、FR-11。

- 操作：分别取消一个任务、触发任务超时、停止工作区、请求销毁工作区。
- 预期：任务取消针对该任务进程范围；超时先尝试终止并验证，未确认清理前保持取消待确认或未知，不因计时到期就标为终态；停止工作区提示影响全部活跃会话。未提供销毁入口时服务端拒绝且无平台副作用；若经范围确认启用，则必须先显式确认持久卷与项目数据后果，再执行和核查级联。
- 安全：不能用“删除整个共享工作区”实现某个任务的普通取消；不能用停止成功替代文件持久化验证。
- 证据：受管进程范围、容器／工作区状态、持久卷与项目文件，及被影响任务的终态或未知状态。

## SC-08：验证隔离与凭据范围

**需求：** FR-08、FR-11、FR-14。

- 前提：准备专用的无敏感内容宿主标记、另一个环境标记、未授权 API 调用和网络测试目标；记录所选模板版本。
- 操作：从工作区尝试读取未挂载宿主标记、访问另一环境文件、使用未授予的控制接口；核对资源和网络策略。
- 预期：结果符合声明策略；容器没有宿主 HOME、Docker socket 或 Kubernetes 管理凭据；普通日志和模型上下文不出现中央控制密钥。
- 网络：必须测试策略允许与拒绝的目标。未配置出站限制时应明确显示未限制，而非给出“完全隔离”结论。
- 证据：容器／Pod／VM 的实际配置和行为、模板版本、拒绝记录、权限测试与脱敏日志。

## SC-09：手机完成一次开发闭环

**需求：** FR-04、FR-06、FR-07、FR-10、FR-14。

- 开发门槛：至少一个手机宽度浏览器视口，先验证布局和会话交互；这不等于发布验收。
- 发布前提：至少一台真实触屏移动设备；记录设备型号、系统、浏览器、视口及输入法版本，明确本次支持矩阵，不据一台设备推断全部移动浏览器兼容。登录须走 FR-14 的认证入口。
- 操作：选择云项目并输入任务；复用 SC-12 真实 CLI 的运行中权限请求和必要澄清，在会话批准／拒绝及回复；搜索并打开文件、编辑保存、查看 Diff，取消另一个任务，再返回会话。
- 预期：不需要在 IDE 终端输入 Agent 命令或向 PTY 回答审批；软键盘弹出后输入框和审批按钮可操作；文件／搜索／Diff 可全宽切换；草稿和滚动位置保留；环境和请求归属可辨认。
- 发布判定：真实设备用例未执行时，FR-10 保持未完成，不得通过 P0 发布门槛；实际失败须修复或经显式范围修订处理，不能用模拟视口通过代替。
- 边界：不要求手机完成复杂多文件重构；证据包括真实设备操作记录、交互事件、保存后的文件读回和取消事实，禁止录入真实敏感账号材料。

## SC-10：中央服务重启后恢复绑定和历史

**需求：** FR-03、FR-09、FR-11。

- 前提：中央已有本地／远程项目、会话、完成任务、一个运行中任务和一条待答审批请求。
- 操作：重启中央 dsh／适配层，再打开项目和历史。
- 预期：环境与会话绑定不丢失；实例世代与核验结果一并恢复；账号凭据通过引用恢复，不从会话文本提取；运行中任务经过重查后更新状态，不凭旧缓存认定还在运行或已结束；待答请求保持原归属，不被自动批准或自动拒绝。
- 证据：直接查存储、API 读回、按项目／任务 ID 检索、磁盘文件及平台真实状态。
- 搜索：如果某类全文索引未启用，明确标为不可用；不能把列表查询当成全文搜索通过。

## SC-11：完整 IDE 打开同一远程项目（第二阶段）

**需求：** FR-12。

**第二阶段复用：** FR-03、FR-04、FR-05、FR-08；不加入第一阶段必测关联，待第二阶段重新验证。

- 操作：在 dsh 点击“在完整 IDE 打开”，进入同一中央 code-server 的指定远端项目和文件。
- 预期：账号认证、环境、根目录、文件和行号正确；文件修改被 dsh 观察，终端／语言服务在目标环境执行；不新增每主机 code-server。深链接按 FR-14 与架构的授权规则校验绑定，过期或被篡改的链接被拒绝。
- 阻断：code-server 不可直接假定支持 Microsoft Remote SSH 扩展。若候选扩展不能同时满足编辑与远端执行，应判定验证未通过，而不是仅展示一个能读文件的 IDE。
- 失败：IDE 尚不支持此环境时明确禁用入口，不回退打开中央同名路径。

## SC-12：在一个环境内运行编程 CLI

**需求：** FR-03、FR-05、FR-08、FR-09、FR-10、FR-11、FR-14。

- 前提：工作区镜像中有至少一个经批准的编程工具及专用账号配置，支持实际权限／澄清事件和响应；为测试准备会触发权限请求的策略及无敏感内容的任务输入，不开启全局自动批准。
- 操作：由中央会话通过环境执行通道运行该 CLI，要求读取随机输入并写出结果；启动后的请求必须经会话 UI 处理，而不是仅审批启动命令。
- 批准：触发实际 CLI 权限请求，展示原任务和绑定的脱敏动作摘要；用户批准后只执行该请求授权的动作，直接读回输出确认结果。
- 拒绝／超时：用独立任务分别拒绝、等待请求超时；受控目标文件保持未修改。CLI 可以报告拒绝或被取消，但取消完成必须检查实际进程。
- 澄清：让任务缺少一个非敏感输入，记录 CLI 的实际阻塞性提问，在会话回答后继续，并核对结果确实使用该答案；不能以向 PTY 输入代替会话响应。
- 断线与旧响应：请求待答或已答但确认丢失时断线，重连后核对原请求状态；不自动批准或重放副作用。过期、重复、跨任务／跨绑定响应均被拒绝；切换项目视图不改变原请求归属。
- 预期：CLI 及其工具活动都留在目标环境；仅注入指定凭据。中央 dsh 不需要在远端安装完整实例。M2 可在桌面会话验证，SC-09 在真实移动设备复用同一交互链路。
- 子任务绑定负向测试：从 A 绑定的会话请求在 B 绑定启动子任务，分别覆盖无授权和用户显式授权；两者都须在派发前拒绝。直接检查 B 的进程和测试文件，确认无新任务、无写入；在 B 对应会话另行发起的合法任务可以执行，不能将其记作 A 的跨绑定子任务。M2 可使用远程 A 与已有本地 B，不要求在单远程环境阶段提前部署第二个远程目标。
- 兼容门槛：现有 ACP／SDK 插件的启动及交互能力必须单独验证；无法兼容时使用明确的受管远程适配器。只能终端交互或只能返回最终文本的后端，不列为首期已支持后端。
- 证据：实际 CLI 版本、进程位置、文件结果、凭据范围、请求／响应 ID、策略版本、用户决定、超时／拒绝事件及取消清理事实；不以启动回执、模型自述或模拟审批消息作为通过证明。

## SC-13：生命周期、实例世代与级联

**需求：** FR-02、FR-03、FR-09、FR-11、FR-13。

- 前提：专用测试环境有历史会话、已完成任务、运行任务和待答审批。各破坏性分支独立准备数据并取得执行授权，不对真实项目做破坏性测试。
- 产品入口分支：通过 Agent Studio 停止并重新启动。对未提供的重建／销毁／凭据替换入口提交服务端请求，必须明确拒绝，核对没有平台副作用。若未来启用这些入口，另行验证确认流程和真实执行，不能仅用拒绝测试替代。
- 外部变化分支：通过受控平台操作分别制造实例替换、销毁和凭据撤销，验证 Agent Studio 的检测与级联。这不是产品内创建／重建能力通过的证据。
- 同世代恢复：重新认证通道并核验后可继续原会话的新任务；旧待答审批失效，原任务按完整运行身份重查。
- 新世代恢复：旧绑定版本关闭派发且保留历史；核验新实例后生成新版本，用户显式打开新会话。旧会话不可发起新任务；旧任务句柄、旧审批、旧 anchor 均不能作用于新实例。销毁后创建替代 workspace 使用新的 bindingId。
- 竞争负向测试：让绑定内 instanceGeneration 与 verifiedGeneration 都保留旧值，而通道已指向新实例，必须拒绝；再测试核验后、派发前重连到新实例，同样拒绝且无新副作用。核对实际通道实例身份，不能仅比较缓存字段。
- 凭据替换：旧连接撤销派发资格；新连接重新认证、核验。无法确认旧通道撤销或原任务退出时保持阻断／未知，不宣称任务已停止。
- 通道对照：覆盖所有已启用通道；未启用通道验证拒绝。证据包括环境状态、世代、绑定版本、SessionBinding、任务与审批状态、远端进程和文件读回。

## SC-14：PTY 终端语义

**需求：** FR-05、FR-08、FR-09、FR-11。

- 前提：目标环境有可观察的交互式程序（例如输出进程组信息的脚本），并准备一个会持续输出的前台程序。
- 操作：打开终端，改变窗口尺寸；向运行中的前台程序发送中断信号；断开中央到远端的连接后重连；结束会话。
- 预期：尺寸变化到达远端 PTY 并反映在程序读取的行列数；中断信号到达前台进程组而不是中央或无关进程；重连后能按输出的游标继续读取，不重复、不丢失已确认的输出；普通 exec 不能被当作终端通过本场景；会话结束后受管进程范围被清理，直接检查远端无残留进程。
- 边界：模型发起的 resize 能力若上游接口不支持，必须在兼容矩阵中声明，不能用人工终端的成功替代模型终端能力。
- 证据：PTY 尺寸读回、信号与进程组事实、重连前后的输出游标、清理后的进程清单。

## SC-15：同一环境内的并发写入与项目边界

**需求：** FR-04、FR-07、FR-11、FR-13。

- 受管分支：两个会话通过受管保存 API，基于同一版本并发写同一文件。一次提交成功，另一次返回版本冲突；读回最终内容、版本令牌和请求结果，不能只检查 UI 提示。
- 外部分支：shell／后台进程直接修改文件后，旧草稿保存应发现已发生的变化。另在最后校验至提交间注入外部写入，记录实际覆盖／冲突结果；没有全写入路径约束时必须声明竞争不受完全保护，不要求外部进程凭空返回 API 冲突。
- 能力判定：受管分支覆盖失败或对外部竞争宣称不存在都判为失败；已声明且如实报告的外部竞争限制不等同于受管保存失效。第二阶段复用同一分类测试 code-server。
- 项目边界：尝试将不同凭据主体或不互信项目登记进同一环境，必须拒绝；同一项目多个根目录按已声明的能力支持或明确禁用，不将“第二个根目录”自动视作第二个安全主体。
- 证据：受管写入结果、直接磁盘读回、外部竞争记录、能力声明和项目登记拒绝记录。

## SC-16：入口认证、授权与路由旁路

**需求：** FR-07、FR-08、FR-14。

- 前提：一个有效登录主体、一个无效或过期凭据、一个不属于当前主体的工作区，以及远程绑定中的文件。
- 操作：不带认证访问受保护端点；用错误主体访问该工作区；在远程文件中使用侧边栏的“在系统打开／显示”与自定义 URL scheme；尝试用过期或篡改的深链接请求资源。
- 预期：匿名与无效凭据被拒绝且原因可区分；错误主体不能读取、启动、停止或审批该工作区的任何资源；本机打开器与 URL scheme 在远程绑定中被拒绝或禁用，不能打开中央同名路径或空 anchor；深链接的越权与过期被拒绝。
- 传输：声明公网使用时，未加密的入口必须拒绝或重定向，不能以明文承载会话凭据。
- 证据：各端点的状态与错误分类、主体与工作区归属记录、被拒绝的打开器调用、访问日志的脱敏字段。

## SC-17：模板交付与实例身份

**需求：** FR-08、FR-13。

- 前提：一份冻结版本的受控模板，包含隔离、资源、允许根目录、运行账号与每次构建生成实例标记的步骤。
- 操作：用该模板创建两个工作区；分别读取模板构建记录和实例记录；再尝试使用同一模板已撤销或未获准的版本、或越界根目录创建第三个工作区。
- 预期：每个实例有唯一、可独立取得的随机标记，记录在项目访问开放前即可读取；两个实例的标记不同，不能互相冒充；已撤销／未获准版本或越界根目录的模板被允许范围校验拒绝，而不是只靠 UI 隐藏；仍获准的回滚版本不因版本较旧而被拒绝。模板版本、策略版本和镜像摘要可读回并与绑定记录一致。
- 负向：伪造或不匹配的实例记录不能建立绑定；模板构建记录缺失时，身份核验判为未通过，不降级为“读写成功即正确”。
- 证据：模板版本与摘要、两次构建记录、实例标记、允许范围拒绝记录、绑定与模板版本的对照。
