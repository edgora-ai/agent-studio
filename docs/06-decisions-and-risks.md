# 决策、假设与待验证项

版本：v0.4；日期：2026-10-30。v0.3 → v0.4 的改动依据见[设计评审记录](07-design-review.md)。

状态词：**已确定目标**来自用户；**建议基线**是可由实验修正的实现选择；**待验证**不是实现承诺；**待决定**需要用户选择。

## ADR-01：一个中央 dsh，不采用多 worker 方案

- 状态：已确定目标。
- 决策：会话、模型配置、插件和 UI 中央维护；远端仅运行项目工具、平台 Agent、轻量 helper 和必要语言服务。
- 理由：避免每个环境安装升级完整 dsh，也避免多个地址、会话和设置分裂。
- 代价：需要适配工作区、Host API 和绕过抽象层的插件；接受必要的最小核心扩展，不承诺完全零改动。

## ADR-02：第一阶段 Coder，控制台不等于隔离机制

- 状态：Coder 是已确定的首期平台；安全隔离是已确定目标；具体模板、连接方式和依赖版本待验证。
- 决策：首期接入 Coder，不自建集群管理产品，不并行实现 OpenSandbox。
- 理由：模板、生命周期、Agent 连接和多种基础设施可复用。
- 约束：核实开源／Premium 边界；选择并验证容器／VM、文件、资源与网络策略，不能仅凭 Coder 工作区存在就宣称安全。若 Coder 无法满足已定范围，记录阻断并提出范围修订，不能在实施中静默换成其他平台。

## ADR-03：先复用社区远程工作区底座

- 状态：建议基线，依赖兼容实验。
- 决策：优先验证 CrazyShout/dsh-ssh-remote 的系统 OpenSSH 路径，参考 remote-vs 的环境路由与 better-sidebar 适配。
- 理由：文件、执行、PTY 和 helper 已有社区实现，不应按全部从零开发估算。
- 约束：npm 同名来源不一致；版本范围不等于运行兼容；**2026-10-30 复核：0.13.2／0.13.3 的 `dshVersions` 不含当前 0.2.1-rc.4**，故该插件当前只是“待验证候选”，不是已选定底座；所查 remote-vs 0.11.1 依赖 0.2.2-alpha.2 相关包，当前组合也须隔离验证，不能据此认定安装必然失败。M1 先执行版本门。
- 升级策略：先隔离测试，固定来源与版本，再决定上游协作／适配／fork，不擅自升级现有服务。发布前按 M4 实测声明的升级与回滚路径，覆盖状态库／配置和 helper；不能将版本锁定或回滚说明当成 NF-05 已通过。

## ADR-04：绑定是身份，anchor 不是代码镜像

- 状态：建议基线；不串环境和不静默同步是已确定目标。
- 决策：项目、环境、根目录、实例世代、策略形成版本化绑定；会话／任务携带绑定，不仅传 cwd。首期子任务与后台任务必须继承主会话的绑定 ID 与版本，不支持跨绑定委派，也不以用户显式授权作为例外；其他环境的任务从其对应会话发起。
- 理由：同名路径、中央目录检查、缓存与后台任务都可能造成错误路由。
- 约束：若需要本地 anchor，只用于受信任的内部工作区兼容映射；适配层在工具路径解析前核对绑定并转换内部上下文。内部上下文必须通过带外标记或专用 API 识别，不能靠路径形状判断；无法判断时拒绝。公开 cwd 只解释为目标环境路径，不识别 anchor 为环境选择器；不保存远端源码副本，不提供失败后的本地执行后备。anchor 与绑定一对一，随绑定失效，不能复用指向新实例。

## ADR-05：不确定时停止派发，而不是猜测成功

- 状态：安全基线；v0.4 复核后区分请求重传与副作用重新执行。
- 决策：禁止本地回退及失联后盲目再次执行副作用。同一请求的安全重传是工程能力，不是由用户开关豁免的安全例外。
- 契约：遵循架构“请求重传与副作用去重”六项条件，覆盖主体／绑定／实例／server session 作用域、参数摘要、执行前原子登记、结果查询、日志保留期与崩溃不确定窗口。重复请求只能关联既有结果或运行句柄；日志过期、身份变化或无法证明未执行时保持未知，不重新执行。
- 验收：按操作类型验证 ACK 丢失、并发重复、同键不同参数、日志丢失／过期及重启／实例切换，并检查副作用计数。只有验证通过的操作类型才可声明安全重传；其余默认禁用。上游“最多重放一次”或返回文本相同均不证明副作用最多执行一次。
- 用户重新发起：这是新操作；原操作未知时先核查并展示重复副作用风险，不能自动换 ID 重跑。
- 代价：需要持久化的任务关联和受控处置入口；安全保持未知不等于 P0 恢复能力已通过。

## ADR-06：侧边栏够用，完整 IDE 放第二阶段

- 状态：已确定目标。
- 决策：第一阶段沿用 dsh 侧边栏的基本编辑体验，补齐环境一致性及必要搜索／Diff；远程结构化 Git 的 P0 仅为 status 与 Diff，其他操作按能力表，不重造完整 IDE。移动端发布必须有真实设备证据；CLI 运行中审批和必要澄清须在会话完成，模拟视口或终端输入不能替代。
- 第二阶段目标：单份中央 code-server 通过受支持的扩展／连接层打开对应项目。
- 关键事实：code-server FAQ 列出 Microsoft Remote Extensions 不可用，不能直接套用桌面 VS Code + Coder 扩展方案。
- 约束：不以每工作区一个 code-server 作为替代；未找到合格方案时第二阶段保持阻断，第一阶段仍可独立使用。第二阶段须重跑 SC-05，分别验证受管保存的版本保护与 code-server 等外部写入的竞争限制，并检查深链接授权／过期；不能只验收“打开成功”，也不承诺任意写入者之间完全无竞争。

## ADR-07：中央身份和远程凭据分离

- 状态：安全基线；首期单受信任使用者为范围假设。
- 决策：控制面密钥／SSH 私钥留在中央受保护存储；项目工具只获得指定账号需要的凭据。所有数据与深链接按身份和绑定授权。
- 约束：不承诺对项目进程不可见的模型密钥代理；helper 与工具同 UID 时不构成强隔离；平台 Agent 凭据和权限需专项检查。
- 扩展：多用户共享、委派账号与组织级权限需另做威胁模型，不能仅开放中央服务公网访问就声称支持多租户。

## ADR-08：模板是交付物，不是部署备注

- 状态：建议基线；模板承担隔离与实例身份是已确定目标（FR-13）。
- 决策：模板版本化，声明并交付隔离、资源、允许根目录、运行账号、网络策略和镜像摘要；每次构建生成随机实例标记并写入可独立读取的构建记录；中央保存 Template／InstanceRecord，绑定携带 `instanceGeneration` 与 `verifiedGeneration`。
- 理由：SC-02、SC-08、SC-17 的身份与隔离验证都依赖一个不经过待测通道的期望值来源；没有模板契约，这些场景无法判定。
- 约束：模板的允许范围由产品服务端校验，不能只靠 UI 隐藏；模板版本、根目录或镜像变化产生新版本；已撤销或未获准的版本及越界根目录必须被拒绝，不因版本较旧就拒绝仍获准的回滚版本。模板变更按 NF-05 纳入升级／回滚验证。

## ADR-09：入口认证与授权独立于工作区认证

- 状态：建议基线；服务入口必须认证是已确定要求（FR-14）。
- 决策：入口层使用 Principal 与加密传输；工作区归属按主体记录；停止、销毁、重建、凭据替换、审批和跨工作区访问校验主体归属，必要时重新认证。Coder 控制面凭据与用户会话分离。
- 理由：移动访问可能经公网、VPN 或私网，不能由“手机”推断必须公网部署；无论哪种方式都要验证主体、绑定与请求归属。同一有权主体在手机与桌面处理同一请求是允许的，但必须一次消费；其他主体或绑定不得越权。
- 约束：首期不做多租户；优先核查并复用现有 dsh 认证，可信代理与 TLS 终止点按部署实际记录。若需新增 SSO／身份服务或公网暴露，另行确认部署变更，不能把“能登录”当作授权模型已完成。

## ADR-10：移动端形态与草稿存储

- 状态：草案建议，尚未选定实现；FR-10 的真实手机闭环仍是 P0。
- 建议：优先评估现有侧边栏全宽化，复用同一文件服务。草稿必须按绑定隔离并保留基础版本；中央或浏览器存储均可满足本设备冲突比较，不能把中央存储说成唯一实现。
- 待核查：现有 UI 槽位、草稿机制、重载后的保留行为与移动浏览器限制，在 M2 给出设计选择和验收证据；不把技术选型一概转交用户。
- 范围边界：跨设备草稿同步不是已确认需求；若选择方案新增同步、中央保存敏感草稿或明显改变用户数据保留方式，先明确范围与隐私影响。尚未选定的建议不是“先按它实现”的授权。

## 待验证项与处理门槛

| 编号 | 问题 | 核查方式／不通过时的处理 |
|---|---|---|
| R-01 | CrazyShout 插件与当前 dsh 的真实契约 | rc.4 未列入 manifest 枚举，peer 约束更宽；兼容性未知，不是已证实失败。先在隔离实例验证当前组合，具体错误出现后再决定升级／适配；不改生产 |
| R-02 | Coder SSH 别名是否贯穿插件并连接预期实例 | 实测 ProxyCommand、Host key、非交互认证及模板构建记录；错误工作区／账号／根目录和过期实例必须拒绝，同连接写读不能自证 |
| R-03 | better-sidebar 哪些入口仍直接访问中央文件／Git／打开器 | 对指定版本审计文件树、watch、搜索、只读 Git、链接、缓存和 `open-external`；逐项改造或禁用，写操作按首期能力表分级 |
| R-04 | 远端编程 CLI 是否能启动并回传实际交互 | 测试 cwd、载荷、stdio、控制句柄、权限／澄清事件、响应绑定、取消和凭据；不兼容时使用明确适配器，终端专用交互不算首期支持 |
| R-05 | 所选基础设施是否满足安全策略 | 实测挂载、UID、资源、网络、节点／元数据与跨环境访问；不满足不得通过安全验收 |
| R-06 | 失联、中央重启后能否重查与停止任务 | 真实故障测试和进程读回；不能确认时保留未知状态并提供受控处置；同时记录恢复窗口 |
| R-07 | 单份 code-server 能否提供完整远程研发语义 | 第二阶段验证扩展许可、文件、终端、Git、语言服务与升级；失败不改成每环境 IDE |
| R-08 | 多 Linux 目标的模板与调度是否依赖付费功能 | 明确 Terraform provider、部署位置、凭据及许可；不满足开源目标时更换路径或显式调整范围 |
| R-09 | 首期性能与限额应如何设定 | 跨主机冷／热连接测量后确定阈值；不以没有数据的时间估计作为承诺 |
| R-10 | PTY 契约能否在所选底座上完整实现 | 实测尺寸、信号、前台进程组、重连游标与清理；模型侧 resize 缺失时声明限制，不能以人工终端替代 |
| R-11 | 同一绑定下实际启用的执行通道是否满足契约 | M1 确认启用路径，逐条验收取消、恢复与超时；未启用路径必须拒绝，不要求同时交付 helper 与每进程兼容路由 |
| R-12 | 大目录与输出上限在所选接口上的实际行为 | 实测目录项数与输出上限；记录诚实失败或截断标记，写入兼容矩阵 |

这些项目不是让用户重新提供已经明确的背景，而是实施实验必须回答的事实问题。新增产品范围或破坏性决定才需要用户选择；可从文档、源码和测试得到的事实优先自行验证。

## 草案建议与范围决定

以下替代初稿的“五项都必须由用户选择”。技术事实由 M1／M2 核查；只有增加范围、外部部署或改变数据保留方式时才需要用户决定。未确认的范围扩展不进入 P0。

| 编号 | 状态 | 事项与处理 |
|---|---|---|
| O-1 | 工程验证，不是安全豁免 | 按 ADR-05 验证去重协议；未证明的操作不自动重传 |
| O-2 | 草案建议 | 优先评估侧边栏全宽化，M2 核查后选择；不预设新增独立移动应用 |
| O-3 | 草案建议；同步扩展待确认 | 草稿存储位置尚未选定；跨设备同步或新的敏感数据集中保留若要增加，另行确认 |
| O-4 | 已有信任边界；登记方式待设计 | 一环境一个项目信任边界不变，同项目多根目录不等于多租户；不新增跨主体共享 |
| O-5 | 工程核查；部署变更待确认 | 优先复用现有认证；新增 SSO／身份服务或公网暴露另行确认 |
| O-6 | 范围扩展待确认 | 产品内重建／销毁／凭据替换入口不列首期 P0；未实现时服务端拒绝，外部变化检测与失效处理仍为 P0 |
