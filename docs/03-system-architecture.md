# 系统架构与边界

版本：v0.4；日期：2026-10-30；本文描述目标架构，不表示已有实现。v0.3 → v0.4 的变更依据见[设计评审记录](07-design-review.md)。

## 1. 总体结构

```text
浏览器／手机：一个 dsh 入口（认证 + 加密传输）
  会话 | 项目环境 | 文件／搜索／Diff | 审批／任务状态
                         |
中央应用与控制面
  dsh：模型调用、会话、插件、现有侧边栏
  Agent Studio：环境目录、模板登记、会话绑定、路由、审计、Coder 连接
    | 本地适配器                     | Coder 适配器
    |                                | 生命周期 API + 工作区连接
  本地项目                         Coder 控制面
                                     |
                    不同 Linux 主机／K8s／VM 基础设施
                                     |
                         项目隔离环境（由冻结版本模板创建）
                    开发工具、平台 Agent、轻量 helper
                    文件、Git、进程、PTY、语言服务

第二阶段：中央 code-server -> 经验证的远程工作区扩展／连接层
```

“中央一套”是逻辑部署与维护边界，不是要求所有服务共用容器、账号或密钥。Coder 控制面和中央 dsh 可以部署在不同位置；必要的服务间连接仍须认证。

## 2. 职责划分

| 层 | 负责 | 不负责 |
|---|---|---|
| 中央 dsh | 会话、模型请求、工具呈现、审批、插件与 UI | 不默认执行远程项目命令，不自动成为断线后备执行机 |
| Agent Studio | 项目／环境身份、绑定、能力路由、模板登记、生命周期衔接、操作审计 | 不重写 K8s 调度器，不自行管理全部云资源 |
| 入口层 | 认证、传输加密、主体与工作区归属判定 | 不把登录成功当作所有工作区的授权 |
| Coder 控制面 | 工作区、模板、构建／启动／停止、Agent 连接信息与应用访问 | 不能仅靠存在控制面就保证容器／网络隔离充分 |
| 执行适配器 | 正确目标上的文件、命令、终端、取消与状态观察 | 不按路径猜目标，不把远程失败转为本地重试 |
| 远端 helper | 版本化、受管的文件／执行／PTY 操作与必要的恢复信息 | 不是完整 dsh，不是安全隔离边界，不要求单独公开管理端口 |
| 模板 | 声明并交付隔离、资源、允许根目录、运行账号和实例标记 | 不是一次性部署说明，不能靠人工记忆保证一致性 |
| 隔离基础设施 | 文件、用户、资源、网络和生命周期策略 | 普通容器不提供独立内核；共享机器不天然是强多租户沙箱 |
| code-server | 第二阶段传统编辑与研发体验 | 不承担第一阶段环境控制面，不默认支持远程开发扩展 |

首期一个远程工作区对应一个项目安全边界；允许同一项目多个会话共享环境，但它们不是互相隔离的租户。不同凭据主体或不互信项目应使用不同环境。该约束不等于“一个项目只能有一个根目录”。多根目录登记方式仍是草案建议；不得据此新增第二套项目权限体系或将同项目第二个根目录一律判为不安全。

## 3. 核心对象与身份

以下为拟新增的内部模型，不是现有 dsh/Coder 的配置格式。

| 对象 | 关键字段／含义 |
|---|---|
| Project | `projectId`、名称、代码来源；不把机器地址当项目 ID |
| Environment | `environmentId`、`kind=local/coder`、生命周期状态、连接状态、能力集、策略引用、当前 `instanceGeneration` |
| CoderTarget | 控制面引用、workspace ID、agent ID、build／`instanceGeneration`、经平台生成或校验的 SSH 目标 |
| Template | `templateId`、`templateVersion`、镜像摘要、资源与网络策略版本、允许根目录、运行账号、构建时注入实例标记的方式 |
| InstanceRecord | 实例标记、workspace／agent／build、世代、模板版本与摘要、允许根目录、策略版本、登记来源；在项目访问开放前取得 |
| ProjectBinding | `bindingId`、版本、project ID、environment ID、目标根目录、策略版本、`instanceGeneration`、`verifiedGeneration` |
| SessionBinding | dsh session ID 与一个明确 ProjectBinding 版本的关系 |
| Execution | 操作 ID、任务 ID、绑定快照、执行通道（helper／兼容路由）、远程运行身份、状态、退出事实、取消状态 |
| InteractionRequest | request ID、任务与绑定版本、类型、有效期、待答／决定／消费／失效状态；不把模型文本当用户批准 |
| Principal | 认证主体、登录方式、会话有效期、可访问的工作区归属；用于审批与破坏性动作授权 |
| CredentialRef | 指向受保护凭据的引用；不在会话、项目 URL 或普通数据库字段内存明文密钥 |

环境生命周期和连接状态必须分开：Coder 的 `running` 不等于 helper 已就绪。内部状态不直接复制某一版 API 的枚举，通过适配器映射并保留原始事实。

### 环境生命周期状态

至少区分：未创建、创建中、已停止、启动中、运行且通道就绪、降级（可连但能力受限）、重建中、停止中、销毁中、已销毁、失败、状态未知。每个破坏性动作（停止、重建、销毁、凭据替换）必须声明前置条件、是否影响活跃会话、对绑定与待答请求的级联结果，以及在部分失败时的停留状态。销毁和重建不能在未确认持久卷后果时执行；停止不能被实现为删除。

### 生命周期与绑定转换（v0.4 修订草案）

ProjectBinding 的版本快照不可原地更改目标或世代。`verifiedGeneration` 来自受信任的核验记录，不能由客户端自行填入；它相等于快照字段本身不构成身份已验证的证据。

| 事件 | 绑定与执行通道 | 会话、任务与审批 |
|---|---|---|
| 停止或身份不再可信 | 暂停新派发，关闭旧通道的派发资格；保留原绑定快照 | 会话可读历史；待答审批失效；运行任务只按实际退出事实转为已停止，否则保持未知 |
| 启动且实例未变 | 重新核验控制面记录和当前通道身份，核验成功后可恢复原绑定 | 原会话可继续新任务；旧审批不复活；原任务按完整运行身份重查 |
| 启动或外部重建产生新世代 | 撤销旧版本派发资格；核验新实例后生成同一 bindingId 的新版本及新的内部 anchor | 首期不迁移旧会话：保留其历史、禁止新派发；用户显式打开新版本的新会话，可引用旧历史但不能继承任务句柄或批准 |
| 根目录、项目身份或策略改变 | 创建新的绑定版本；更换 workspace 身份或项目身份时创建新的 bindingId；重新授权和核验 | 旧会话只读，新任务从对应新会话发起；不得静默改写 SessionBinding |
| 销毁 | 原绑定标记失效并保留审计，不删除历史；重建替代 workspace 使用新 bindingId | 待答请求失效；任务根据销毁／进程事实终结或保持未知；不得关联到替代实例 |
| 凭据替换或撤销 | 撤销旧连接使用资格并重新认证；无法确认撤销或新身份时保持阻断 | 旧待答请求失效；运行任务重查，不能把换凭据等同于任务已退出 |

重建、销毁及凭据替换的产品内执行入口是待确认的范围扩展，不是首期强制交付项。未实现时，服务端必须明确拒绝请求且不产生平台副作用；对平台外部发生的这些变化，仍必须执行上述失效与恢复规则。不能用“未提供按钮”代替服务端拒绝。

### 执行状态

建议至少区分：排队、启动中、运行中、取消待确认、已取消、已完成、已超时、已停止（环境停止导致）、失败、状态未知。只有可观察的远端事实才能将未知状态转成终态。“已超时”“已停止”与“已取消”必须可区分，用于 SC-07 的证据。

## 4. 路由不变式

1. 每次文件、搜索、Git、终端、工具调用都携带或能无歧义解析到绑定身份。
2. 一个任务启动后固定绑定快照；切换项目视图不改变旧任务、终端和未保存编辑器的目标。
3. 项目切换选择另一绑定的会话；已有会话的迁移不是第一阶段隐式行为。
4. 同一路径字符串在不同环境中可以表示不同文件；缓存、锁、版本戳、搜索结果和打开标签必须包含环境身份与世代。
5. 若现有 dsh 注册工作区时要求真实本地 cwd，可使用空的本地 anchor 保存内部兼容映射。anchor 不是代码镜像，不是公开工具参数中的环境选择器，也不能成为实际执行目录或失败回退。
6. anchor 删除、映射不存在、环境停止、绑定失效、世代不符或路径越界都应拒绝操作。
7. 只能由明确的本地绑定选择本地 provider；不能采用“远程识别失败就交回 local provider”的策略。
8. 相对路径、符号链接、编码、分隔符和规范化由目标执行世界处理；中央不能用自己的 `realpath` 判断远程文件存在与否。
9. 会话绑定优先于工具参数中的 cwd。远程会话的公开 cwd 始终解释为该绑定环境中的路径；不识别本地 anchor 映射，不以 cwd 切换 provider。越出绑定根目录、携带其他绑定身份或要求中央执行的调用必须拒绝。首期所有嵌套子任务和后台任务必须继承主会话的绑定 ID 与版本，不接受跨绑定委派，即使用户在当前会话明确授权也不能作为例外；需要在另一绑定执行时，必须打开该绑定的会话并另行发起任务。
10. 派发前核对绑定快照、受信任控制面／实例记录和当前已认证执行通道的 workspace、agent、实例世代；不能只比较绑定内两个可能一起过期的字段。helper／连接会话必须固定在已核验实例上，请求携带该实例身份，身份不符、过期或无法核验时拒绝。核验后的重新连接必须重新检查，不得把旧核验结果沿用到指向新实例的 SSH 别名。失效后原子关闭该绑定版本的新派发资格；已经派发的操作单独重查，不宣称它们已停止。
11. 系统的本机能力不能成为远程绑定的旁路。侧边栏与 dsh 的“在系统打开／显示”、`file:` 与自定义 URL scheme、本机打开器和快捷键，在远程绑定下必须被拒绝或显式禁用；只隐藏按钮、不拦截底层调用不算满足。
12. 适配层必须能判定一次调用来自受信任内部上下文还是公开工具参数。该判定不能只依赖路径形状；无法判定时拒绝。

### 内部 anchor 与公开 cwd 的处理顺序

1. 工作区登记层持有 anchor 与绑定版本的受信任映射；模型和外部 API 不获得设置、替换该映射的能力。
2. 若 dsh 内部工作区上下文使用 anchor 作为兼容 cwd，适配层必须先核对会话绑定与精确映射，再将内部上下文转换为绑定环境及其根目录；转换发生在工具路径解析前，anchor 不作为目录发给远端执行器。
3. 内部上下文的识别使用带外标记或专用登记 API，而不是比较路径字符串。缺少标记的调用一律按公开参数处理。
4. 公开工具参数中的 cwd 不进入上述内部映射逻辑。省略时使用绑定根目录；相对路径从该根目录解析；绝对路径在目标环境解析并检查边界。无法满足边界时拒绝，不尝试中央目录。
5. 路径字符串恰好与中央路径相同，不代表中央执行授权。合法性由绑定身份、目标命名空间和根目录决定，不能仅靠字符串相同／不同来判断环境。
6. 已删除、未知或属于其他绑定的内部 anchor 必须在派发前被拒绝。若候选插件只能让公开 cwd 充当环境选择器，必须先加适配或核心扩展，不能直接按原行为启用。
7. anchor 由登记层按绑定一对一创建，随绑定失效或删除而失效；不允许复用旧 anchor 重新指向新实例。删除后的旧映射必须不可恢复地失效。

绑定根目录是产品路由和路径策略，不是 OS 安全围栏。真实访问限制还依赖工作区的用户、挂载和运行策略。

## 5. 能力适配契约

### 文件与搜索

需要支持路径解析、元数据、目录分页或明确上限、文本／字节读取、原子或受保护写入、文件变化通知、版本守卫、错误分类与取消。以当前安装 dsh 的真实接口为准，不能仅实现下载／上传。

- 编辑器保存前验证观察到的文件版本；不悄悄覆盖 Agent 或其他客户端的修改。
- 经受管保存接口写入时携带版本令牌；helper 串行化同一文件的受管写入，并在提交前校验版本。两个受管写入者基于同一版本保存时，后者必须返回冲突，不得无声覆盖前者。
- shell、编程 CLI、构建工具及未适配的 code-server 可以直接写磁盘，不天然遵守版本令牌或协作锁。已观察到的外部改动必须使旧草稿保存冲突，但不得宣称消除了检查到提交之间的所有竞争；候选插件报告 `externalWriterRaceFree: false`。能力声明和 UI 必须披露此边界，SC-05／SC-15 分别验证受管写入与外部写入。
- 若将来要求任意进程之间绝不覆盖，须另行设计能约束全部写入者的机制并修订范围。文件监听、普通协作锁和一次测试通过不能作为该保证的证据。
- 文件监听只触发重新读取，不能作为内容真实性或写入成功证明。
- 搜索工具的可执行程序必须在目标环境解析，不能把中央 npm 包中 ripgrep 的绝对路径发给另一台机器。
- 文件链接与引用需要环境身份；禁止把远程显示路径重新解释成中央 `file:` 路径。
- 已知不支持分页的目录接口必须在能力声明中标注，并给出诚实失败或截断标记；不能把截断结果当成完整目录。

### 命令与后台任务

需要 argv/cwd/env、stdin/stdout/stderr、流式与有界输出、退出状态、超时、取消、受管进程范围清理和必要恢复信息。真实 PID、控制通道和句柄语义必须按安装版本核对，不能把源码 POC 的假设当成永久接口。

- 进程仅接收显式批准的环境和凭据；中央控制凭据不隐式继承。
- 路径和参数通过结构化协议传输，不拼接未经转义的 shell 字符串。
- 连接退出不代表远端任务退出；取消在确认清理前保持待确认状态。
- 禁止失联后盲目再次执行副作用。重发同一请求与再次执行操作不是同一概念：只有经验证的去重协议允许安全重传；用户开关、重传次数上限和相同返回值都不能替代证明。具体规则见下节及[决策与待验证项](06-decisions-and-risks.md) ADR-05。
- 同一绑定可能存在两条执行通道（helper 与每进程兼容路由）。实际启用的每条通道须分别声明并验收取消、恢复和超时语义；未启用路径必须拒绝，不要求交付第二条通道，也不能以一条通过代表其他已启用通道可用。

### 请求重传与副作用去重

安全重传是按操作类型声明、经 M1 验证后才可启用的协议能力，不是对任意 shell 命令的幂等承诺。

1. 去重键至少包含主体、绑定 ID／版本、实例世代、远端 server session 和 operationId；请求的动作及规范化参数摘要必须一致。同键不同参数必须拒绝。
2. 服务端在执行前原子登记操作并拒绝重复派发；重复请求只返回既有结果、既有运行句柄或处理中状态，不再次启动操作。确认丢失时先查询该操作，而不是生成新 ID 重跑。
3. 明确去重日志的保留期限，并保证它覆盖声明的重传／恢复窗口；过期、日志丢失、server session 重建或实例世代改变时，不再自动重传有副作用请求，保留未知并要求受控处置。
4. 对“副作用已经发生、结果尚未落盘”窗口单独做故障注入；无法证明未执行时不能再次执行。不能把 operationId 存在本身当作 exactly-once 保证。
5. 记录重传、去重命中、拒绝与副作用计数。测试须包含 ACK 丢失、并发重复请求、同键不同参数、日志过期、daemon 重启和实例切换。
6. 用户显式重新发起是新的操作，但原操作未知时须先展示重复副作用风险并核查原任务，不以“新 ID”自动绕过去重保护。

未通过上述验证的操作类型默认禁用自动重传；读取或查询操作也必须有超时和重试上限。恢复窗口与去重日志保留期分别声明，不能混为一项。

### 会话内审批与必要澄清

启动 CLI 的授权不等于批准其后续所有动作。首期支持的编程 CLI 必须能将实际运行中的权限请求和阻塞性澄清转成中央会话事件，而不是只显示终端提示或让用户向 PTY 输入答案。

- 每个请求携带唯一 request ID、task ID、绑定 ID／版本、请求类型、脱敏动作摘要、选项和有效期。审批只能由有权用户作出；项目内容或模型输出不能充当用户批准。
- 授权判定依据 Principal 与工作区归属：不同主体不能批准不属于自己的工作区请求；多标签页／多设备下同一主体的决定必须一次性消费。
- 权限请求支持批准／拒绝；必要澄清支持在会话回复。预先允许或拒绝的行为必须来自用户明确配置的版本化策略，并记录策略决定；不能通过全局自动批准来冒充交互能力验收。
- 响应只对原任务、原绑定、原请求有效，并且最多消费一次。切换可见项目不改变待答请求归属；已过期、重复或指向其他绑定的响应必须拒绝。
- 拒绝或超时后，不得执行请求授权的动作；可让 CLI 报告拒绝或取消该任务。取消仍须按远端实际清理状态确认，不能将拒绝请求等同于所有进程已退出。
- 断线时不自动批准，不盲目重发已答请求。重连后先核对原请求及决定状态；无法确认则保持待确认或中止受管任务，不把旧批准套用到新任务。
- 无法提供这些事件／响应语义、只能靠交互终端操作的 CLI，不得列为首期已支持后端。可以继续单独实验，但不能通过 SC-12 或 FR-10 验收。

### 终端（PTY）

PTY 是独立能力，普通 exec API 不能冒充终端。首期契约至少包括：

- 尺寸：创建时指定行列，运行中可改变；若模型侧接口不支持 resize，必须在兼容矩阵声明并以人工终端验收为限。
- 输入／输出：原始字节流，输出有界并可继续读取；游标在重连后仍能定位到已确认位置，不重复交付已确认输出。
- 信号：向远端终端发送中断、终止等信号时作用于前台进程组，不波及中央或无关进程。
- 前台进程组：可观察并用于信号与清理；会话结束时清理整个受管范围。
- 断线恢复：在恢复窗口内可重连并继续读取输出；超过窗口按状态未知处理，不能声称已结束。
- 清理：关闭终端后受管进程不得残留；残留必须被检测并显示为未清理。

### Git 与侧边栏

沿用现有侧边栏，改造直接访问中央文件系统、`fs.watch` 和本地 `git` 的路径。首期远程结构化入口只将 `status` 和工作树／暂存区 Diff 列为 P0；其他操作按[首期 Git 能力表](02-features-and-scenarios.md)分级，不通过隐藏的中央执行补齐按钮。

结构化入口未提供，不等于 OS 层禁止该 Git 命令。用户明确授权的通用命令仍按 FR-05 在绑定环境执行并保留副作用与凭据审批；不能把命令运行成功计作侧边栏写操作已经实现。本地已有功能按原行为回归。

侧边栏的“在系统打开／显示”和 URL scheme 启动属于本机能力，在远程绑定下按路由不变式 11 拒绝；不能把空 anchor 或中央同名路径交给操作系统打开。

## 6. 时限、恢复窗口与重试

- 启动、任务、审批、终端恢复和操作超时必须有默认值、配置归属与超时后的状态迁移。具体数值在 M1 实测后记录，不在文档阶段猜测；没有上限的等待不被接受。
- 恢复窗口指断开后远端仍保留任务、PTY 与输出游标的时长。窗口内重连必须能按已保存身份重查原任务；窗口外必须显示为恢复不可用，而不是成功或失败。
- 重试只用于明确可重试的读操作。带副作用的调用按 ADR-05 处理；重试次数与退避有上限并可观察。

## 7. 状态与数据位置

| 数据 | 位置及策略 |
|---|---|
| dsh 会话、模型设置、插件配置 | 中央 dsh 现有持久化；插件不另复制一套远程会话库 |
| 环境目录、模板／实例记录、绑定、任务／交互请求关联、审计 | 首期拟用中央插件的 SQLite 存储；版本化迁移并可备份恢复；未完成请求不能因重启丢失归属或被重新自动批准 |
| 控制台密钥 | 中央受保护 secret 存储；首期可使用私有目录与 0600 文件，数据库只存引用；这不等于静态加密 |
| 项目代码和构建产物 | 所属环境的持久卷／磁盘；创建、停止、重建、删除的保留规则必须明确 |
| helper 运行状态 | 远端私有运行目录；按任务或环境保留必要句柄，不承诺宿主故障后天然恢复 |
| 缓存、临时输出和 spill | 有界并绑定环境；说明保留期，禁止缓存中夹带控制密钥 |
| 编辑草稿 | 必须按绑定版本隔离并保留基础文件版本，属于用户输入，不作为磁盘真值。中央存储或浏览器存储尚未选定；ADR-10 仅给出建议，不授权提前实现；跨设备草稿同步不是当前已确认范围 |

中央备份不等于远程代码备份。Git 检出、卷快照和人工备份各自定义，不自动做双向同步。秘密管理、SQLite 文件归属和迁移细节属于实施设计，在接入真实凭据前落实。

## 8. 安全边界

### 入口、认证与授权

- 服务入口必须认证；声明远程／移动使用时必须使用加密传输，明文入口拒绝或重定向。
- Principal 记录登录方式、会话有效期与可访问的工作区归属。停止、销毁、凭据替换、审批和对其他工作区的访问属于关键动作，必须校验主体归属；必要时要求重新认证。
- 后端服务间连接（dsh 到 Coder、适配层到 helper）各自认证，不复用用户会话凭据。
- 认证失败、越权、过期与路由失败分别可观察，不合并为一个通用错误。
- 多用户共享与组织级权限仍不在首期范围；开放公网访问不构成多租户支持。

### 中央与远端

中央持有的 Coder 管理凭据、SSH 私钥和平台控制能力不能注入编程工具环境。远端编程 CLI 可以获得其专用业务／模型凭据，但该进程通常仍能读取自己的凭据；不声称已经实现对模型进程不可见的密钥代理。

Coder Agent 和 helper 的凭据范围、UID、运行目录及 `/proc` 可见性需要审计。helper 若与项目工具同 UID，不构成两者之间的可信隔离；不能把签名／哈希校验误当作运行后不可篡改保证。

### 工作区与宿主

模板默认不得挂载宿主 HOME、Docker socket、管理 kubeconfig 或宿主根目录，不使用 privileged／host PID／host network 作为便捷默认值。设置资源配额和受控持久卷；系统用户与可写目录明确。

网络策略须覆盖模型／Git／依赖仓库等所需访问，并明确宿主、其他工作区和云元数据端点的可达性。未经验证的普通 bridge 网络不能标注为网络已隔离。若基础设施不能满足选定策略，应阻止安全验收，而非仅显示绿色沙箱图标。

### 本地模式

本地项目仍按现有 dsh 本地权限运行，不能因同一产品也支持远程沙箱就宣称本地已隔离。界面显示本地／远程及策略档位；远端不可用绝不触发本地执行。

## 9. 集成与非保证项

- 现有 dsh 的 provider／consumer 存在 Cordis context 与隔离 realm 约束；中央 API 和侧边栏不一定使用 Agent 内的同一 provider。
- 会话绑定和 Host API 路由可能需要少量 dsh 核心扩展；优先插件实现，但不以零核心改动为硬性前提。
- 第三方插件直接 Node FS／child_process 调用需要审计与适配，不承诺全部透明工作。
- 第一阶段 Linux 工作区优先；Windows 远端、桌面系统打开器和全插件兼容不在范围。桌面打开器不在范围是指不作为远程文件的打开方式，不表示可以放任其访问中央同名路径。
- 当前安装产物和检出的源码接口有差异，必须按锁定版本的类型及真实调用验证。

具体依赖与候选复用点见[集成方案](04-integration-plan.md)，风险决策见[决策与待验证项](06-decisions-and-risks.md)。
