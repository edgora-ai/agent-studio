## 2. 阶段门槛

### M1：先消除兼容性与平台不确定性

- 执行版本门：分别记录 manifest 枚举版本、peer 约束和安装产物，在隔离测试实例验证当前组合。当前源码基线为 dsh／Gateway `0.2.1-rc.5`，以[来源锁](../profiles/agent-studio-preview/sources.lock.json)为准；DSH 会持续发布，后续升级用[来源核对工具](../scripts/dev/source-lock.mjs)列出差异、显式复核实现与投影回归后更新快照，不永久固定历史版本。候选 manifest 的 `dshVersions` 枚举不含某版本不证明运行不兼容；也不假定未复核的新版自动兼容。生产升级与部署仍单独授权，不在本文档阶段隐式执行。
- 锁定 dsh、侧边栏、远程插件、helper、Coder CLI／Server、模板／镜像版本及来源。
- 验证目标插件不是 npm 同名的另一个项目；保存发布清单与完整性结果。
- 冻结一份模板契约：隔离、资源、允许根目录、运行账号、网络策略与实例标记生成方式；完成 SC-17 的模板交付检查。
- 确定 NF-07 的时限与恢复窗口初值、去重日志保留期，以及已知大目录接口的上限（NF-04）。对拟启用安全重传的操作执行 ACK 丢失、重复请求、日志丢失／过期及实例切换验证；未经验证的操作禁用有副作用请求自动重传。
- 在不影响现有服务的 profile／测试实例进行，不直接升级生产。
- 真实 Coder 工作区别名经 OpenSSH、插件、helper 三层连通。
- 先用模板构建记录核验预置实例身份，并证明错误工作区、账号、根目录和过期实例会被拒绝；不能用同一连接内写入再读回的随机值自证目标。
- 身份通过后完成独立随机文件读回、命令执行、PTY 输入、尺寸变化与取消；验证远端不可用时不在中央执行。
- 拦截检查：本机打开器、URL scheme 与快捷键在远程绑定下的行为必须实测并记录（SC-16 的路由旁路部分可在 M1 先做技术验证）。
- 输出接口覆盖及缺口清单，才决定复用、适配或最小核心修改。

若当前 dsh 与目标插件不兼容，记录具体符号／调用／错误和可替代版本。不得仅根据 peer 范围认定通过，也不得为了装插件自动切到 alpha。

### M2：单环境完整闭环

先实现绑定与路由，再接文件／进程，最后接侧边栏和搜索，不先做一个能展示但执行目标不一致的环境选择器。

必须通过 SC-01、SC-02、SC-03、SC-05、SC-12、SC-14。远程模式中不支持的工具或插件功能明确拒绝，不留下隐式中央执行入口。SC-02 的启动已有工作区与新建工作区两条分支均须通过。主会话与子任务必须使用相同的绑定 ID 与版本；即使请求带有用户明确授权，跨绑定子任务也必须在派发前拒绝，并验证另一环境没有启动进程或产生写入。

SC-03 必须区分内部 anchor 转换与公开 cwd 解析，并验证无法分类时拒绝。SC-12 必须触发真实 CLI 的运行中审批／澄清，验证批准、拒绝、超时、断线及过期／跨绑定响应，不能只审批启动或开启全局自动批准。SC-14 必须验证 PTY 尺寸、信号、前台进程组、重连游标与清理，不能用普通 exec 冒充。M2 可用桌面／模拟视口验证协议，但不因此判定 FR-10 的真实移动端发布验收通过。

### M3：跨主机、生命周期与故障安全

- SC-04 必须使用两个不同机器／节点的真实环境，且由冻结版本模板创建。
- SC-06、SC-07、SC-13 覆盖失联、未知、取消待确认、超时、工作区停止、外部重建／销毁、实例世代失效及绑定版本／会话转换。未提供的破坏性产品入口以服务端拒绝及无副作用验证，不把独立重建／销毁 UI 新增为 P0。
- SC-08 验证声明的安全策略；不能仅检查配置值。
- SC-15 分别验证受管写入冲突、外部直接写入的已声明竞争限制，以及一环境一个项目信任边界；不将同项目多根目录自动视作多租户。
- SC-16 验证入口认证、授权、传输与路由旁路。
- SC-09 必须在至少一台真实触屏移动设备上完成，记录设备／系统／浏览器及输入法版本；复用 SC-12 的运行中审批／澄清链路。模拟视口只算开发阶段证据，不能替代 FR-10 发布验收。
- SC-10 验证中央存储与重启恢复，包括待答请求归属与实例世代恢复。

对基础设施不支持的 P0 策略或恢复能力明确判定未满足，不以文档说明代替验收。SC-06 必须证明在声明的恢复窗口内，连接恢复且原环境健康时能够重查原任务，并取消仍在运行的原任务；仅显示未知状态和能力限制属于故障安全保护，不是恢复能力通过的证据。窗口外的用例单独记录，不当作通过。

### M4：第一阶段发布

在约定版本矩阵完成回归，保留可复现命令、脱敏输出、状态与数据证据。所有 P0 需求与适用的非功能要求通过，P1/P2 不冒充已经完成；回滚能力必须实际验证，不能只提供说明。

**NF-05 升级／回滚发布门槛：**

1. 明确本次支持的升级源版本、候选版本、回退目标及转换路径；覆盖中央 dsh／插件、helper、插件状态库、模板版本和配置，并注明未发生版本变化的组件。首个发行版可使用已运行并持有测试数据的预发布基线；未经实测的路径不能列为已支持。
2. 在隔离测试环境预置本地／远程项目、既有会话、版本化绑定、任务历史及专用测试凭据引用。停止接收新任务，将运行任务和待答交互完成或取消并确认，再取得一致的状态与配置备份；未知任务未处理前不能开始破坏性恢复。
3. 实际执行一次受支持的完整路径：基线 → 候选版本 → 回退目标。升级后先验证数据迁移、文件／命令路由、helper 版本、模板版本和连接，再按声明路径回滚。外部 Coder／基础设施服务若未变更，保持其原版本；若变更，则需另有对应的官方兼容与恢复验证，不能假定任意降级可行。
4. 回滚后直接检查持久存储、通过 API 读回并按 ID 检索：既有会话与绑定的 ID／版本、实例世代、环境身份、任务历史及凭据引用均按声明保留。实际验证旧版本与恢复的 helper 能协作，本地和远程读写／命令目标正确，不将历史任务或批准请求自动重放。
5. 数据库不能直接降级时，必须预先声明备份恢复路径并实跑；只替换旧二进制不算回滚。备份点之后若已接收新的持久化写入，不能直接用旧备份覆盖，必须先完成其保留／协调，否则判为当前条件下不可安全回滚。中央状态回滚不撤销远端文件修改和其他副作用，不得隐式回退项目卷。
6. 保存升级及回滚前后的版本、备份／恢复记录、数据对照、helper 和真实会话调用证据。升级与回滚任一环节失败或未执行，NF-05 未通过，阻断 M4 发布；修复后重跑，不能以回滚文档替代证据。

另行提供可复现的回滚与卸载步骤，说明对中央状态、凭据引用和远端项目数据的影响；验证过的回滚路径不代表卸载可以无确认删除数据。

### M5：第二阶段独立门槛

先证明 code-server 兼容远程扩展及许可可行，再做入口集成。必须满足 SC-11 的单份部署、远程文件与执行语义，并重跑 SC-05，分别验证受管保存的版本保护与 code-server 等外部写入的竞争限制，不将三方并发测试表述为任意写入者之间完全无竞争；深链接必须验证授权与过期。失败不能用每工作区 IDE 替代原目标。该阶段不阻塞第一阶段。

## 5. 测试层级

### 契约与单元测试

覆盖绑定解析、状态机、路径规范化、权限判断、版本冲突、操作 ID、交互请求、错误分类和日志脱敏。特别测试内部 anchor 到绑定上下文的转换、公开 cwd 不选择环境、无法分类时拒绝、越界路径、已删除／跨绑定 anchor、同名根目录、符号链接、缓存串环境、实例世代不符时拒绝，以及环境生命周期级联。交互测试覆盖响应有效期、重复消费、跨任务／跨绑定响应及重启后待答请求归属。

### provider／helper 集成测试

独立调用实际文件、执行和 PTY provider，验证协议与生命周期；包括原始管道、输出上限、取消、退出、清理、PTY 尺寸与信号。这一层不能证明真实主会话已获得正确工具。

### 真实 dsh 端到端

- 从实际会话启动工具，检查真实模型请求工具目录及调用事件。
- 使用随机输入和实际环境标记；禁止父代理代读远程测试文件或使用其他 provider 代跑。
- 将最终结果与远端实际文件／进程状态严格比较。
- 检查模型与人工 UI 的操作路径均经过绑定路由，不能只测其中一条。
- 检查子代理和后台任务继承目标，不能把成功启动回执当作完成结果。
- 分别覆盖所有已启用的执行通道；未启用的兼容通道验证明确拒绝，不要求为了验收而引入额外通道。

### 浏览器与移动端

验证登录、项目选择、侧边栏、保存冲突、搜索结果定位、Diff、审批、取消、生命周期动作和环境状态。浏览器脚本记录 JS 错误与失败请求；手机视口和真实设备分别注明覆盖范围。

## 6. 数据与认证验证闭环

任何新增绑定／审计／状态存储都必须执行：

```text
写入 -> 直接检查实际存储 -> API 读回完整字段 -> 按 ID／筛选检索
```

会话沿用 dsh 存储时，也要核对真实持久内容，而不是只看返回值。全文搜索若未启用须明确标注，不能将列表检索等同全文搜索。

认证验收按部署实际路由分类：公开健康端点按约定无需认证，受保护端点匿名／无效凭据被拒绝，正确身份成功；还要测试错误用户／错误工作区的访问、过期会话、错误主体的审批与破坏性动作。声明公网或移动使用时，验证明文入口被拒绝或重定向。不要强行将现有受保护根页面改成公开，也不要仅测 HTTP 状态而忽略资源权限。

所有证据不得包含登录 token、私钥、控制台密钥、真实敏感项目内容或完整代理凭据。

## 7. 安全与生命周期实测

| 边界 | 配置检查 | 行为验证 |
|---|---|---|
| 文件 | 挂载、UID、可写目录、卷归属 | 专用宿主／跨环境标记的允许和拒绝访问 |
| 资源 | CPU、内存、PID／存储上限 | 有界、经授权的限额触发测试；不对共享机器做失控压测 |
| 网络 | 出站、其他环境、节点／元数据访问策略 | 仅使用测试目标验证允许／拒绝；不扫描无关网络 |
| 凭据 | 注入清单、权限、secret 引用、替换流程 | 中央控制密钥不进入子环境和普通日志；替换后旧连接失效 |
| 进程 | 受管范围、超时、停止协议 | 取消后直接检查进程范围／容器状态，不以 SSH 断开推断停止 |
| 数据 | 停止／重建／删除与卷策略 | 直接读回项目文件，确认停止不等于删除 |
| 模板 | 版本、摘要、允许根目录、实例标记 | 已撤销／未获准版本与越界根目录被拒绝；仍获准的回滚版本不因较旧被拒绝；标记来自构建记录 |
| 入口 | 认证、加密、主体归属 | 匿名、无效、越权分别被拒；打开器与 scheme 无旁路 |

若某个能力只能得到“请求已发送”，证据必须标注未确认；不能把它记录为远端动作已完成。

## 8. 性能与可用性记录

分别记录冷启动、热连接和断线恢复。测量目录读取、搜索首结果、文件保存、命令首输出、PTY 首输出与尺寸变化、取消完成、UI 状态变化和资源占用；同时记录主机位置、网络、文件规模及版本。

首次实验用于设定后续回归阈值，不能预先承诺固定毫秒级响应。超出上限的目录、文件和输出应明确提示或分页，不静默截断后当成完整结果。

## 9. 证据组织与完成标准

实施时在独立测试输出目录保存：版本清单、来源校验、模板与实例记录、配置脱敏快照、测试输入哈希、工具事件、远端读回、生命周期记录、浏览器结果、数据存储查询与最终检查表。该目录不得自动提交账号材料或真实用户代码。

每项结果标注：通过、失败、未执行或环境不支持；附命令和实际输出。文档静态通过、独立 provider 通过、真实 dsh 通过和安全策略通过是不同结论。

**第一阶段必需：** FR-01、FR-02、FR-03、FR-04、FR-05、FR-06、FR-07、FR-08、FR-09、FR-10、FR-11、FR-13、FR-14。

**第二阶段独立：** FR-12。

第一阶段发布至少要求：

- 上述第一阶段 P0 需求的正式关联场景全部通过；FR-12／SC-11 不阻塞第一阶段。
- NF-01 至 NF-08 的全部映射场景与检查项通过；失败或未执行不得以“已有记录”代替通过。
- 本地项目无回归；两个跨机器／节点目标不串路由。
- 无未经说明的中央执行、未确认取消或遗留资源。
- 实际存储、API 读回、检索和中央重启恢复通过。
- 模板版本与实例身份在项目访问开放前可独立核验；重建后旧核验失效。
- 入口认证、授权与打开器旁路验证通过。
- NF-05 按 M4 完成实际升级及回滚：保留既有绑定／状态与凭据引用，helper 和真实会话调用可用；未执行或失败不得发布。
- 构建与启动无错误；页面无未处理异常，日志已脱敏。
- 兼容性、未支持功能、权限、停止／重建／删除语义和经过实测的回滚步骤可供复现。
